# Book Catalog (`book_catalog`)

Навчальний проєкт із розроблення програмного забезпечення мовою **Dart** (SDK `^3.13.2`).

---

## Лабораторна робота №1: Функції та колекції

Консольна програма для безпечного розбору, валідації, фільтрації, групування, сортування та агрегації записів предметної області **«Каталог книг бібліотеки»** без використання класів (`class`).

### 1. Обґрунтування вибору архітектури та типів даних

1. **Модульна функціональна архітектура (`lib/` + `bin/`)**:
   - Уся чиста бізнес-логіка (типи даних, константний набір CSV, парсинг, валідація, конвеєри обробки, замикання, форматування звіту) розміщена в бібліотечному модулі `lib/book_catalog.dart`.
   - Вхідна точка `bin/book_catalog.dart` відповідає виключно за запуск сценаріїв демонстрації та виведення сформованого звіту в консоль.
   - Такий поділ дозволяє незалежно тестувати всі функції в `test/book_catalog_test.dart` та підготувати кодову базу до переходу на ООП у Лабораторній роботі №2.

2. **Вибір типів даних (відмова від `class` на користь `Record`, `List`, `Map`)**:
   - **`BookRecord` (іменований запис / Record)**: використовується для представлення окремої книги (`id`, `title`, `author`, `genre`, `year`, `pages`, `rating`, `isbn`, `addedDate`). Іменовані записи в Dart 3 забезпечують строгу статичну типізацію, незмінність (immutability) та автоматичну структурну рівність (`==` і `hashCode`) без оголошення класів.
   - **`ParseResult` та `ValidationResult` (Records)**: замість викидання та перехоплення винятків (`try/catch`) при очікуваних помилках розбору невалідних CSV-рядків використовується запис-результат `({int lineNumber, String rawLine, BookRecord? book, String? error})`. Це робить потік керування детермінованим та явно відображає можливість помилки у сигнатурі функції.
   - **`List<BookRecord>` та ліниві конвеєри `Iterable`**: вхідні дані та відфільтровані вибірки зберігаються у типізованих списках `List`. Агрегація виконується декларативними ланцюжками `.where(...).map(...).fold(...)` без циклів із мутабельними накопичувачами.
   - **`Map<String, List<BookRecord>>` та `Map<String, GenreStats>`**: асоціативні словники застосовуються для групування книг за категорійною ознакою (`genre`) зі складністю доступу $O(1)$ за ключем жанру.
   - **`StringBuffer`**: використовується у функціях `buildReport` та `buildFullDiagnosticReport` для ефективного формування багаторядкового звіту без алокації проміжних рядків через оператор `+=`.

3. **Пояснення роботи замикань (Closures)**:
   - Функція `createRecordCounter([int initialValue = 0])` створює локальну змінну `var count = initialValue` та повертає запис із трьома анонімними функціями (`increment`, `current`, `reset`). Ці функції захоплюють змінну `count` та параметр `initialValue` із лексичного оточення `createRecordCounter`, зберігаючи актуальний стан лічильника між викликами.
   - Функція-фабрика предикатів `createBookFilter({String? genre, double minRating, int? minYear, int? maxYear, int? minPages})` захоплює нормалізовані параметри фільтрації у замиканні `bool Function(BookRecord)` для подальшої передачі в `.where(...)`.

### 2. Обґрунтування використання `!`, `late` та `dynamic`

У межах Лабораторної роботи №1 у коді проєкту (`lib/`, `bin/`, `test/`):
- **Оператор `!` (null assertion operator)** — **не використовується (0 входжень)**. Замість примусового розпакування nullable-значень застосовано безпечне звуження типів через локальні перевірки `if (value != null)`, фільтрацію колекцій методом `.whereType<BookRecord>()` та оператор `??`.
- **Ключове слово `late`** — **не використовується (0 входжень)**. Усі змінні ініціалізуються безпосередньо в момент оголошення як `final` або `const`.
- **Тип `dynamic`** — **не використовується (0 входжень)**. Усі функції, колекції, записи та акумулятори у `fold<T>` мають явні статичні типи.

### 3. Обґрунтування сторонніх залежностей із `pub.dev`

У секції `dependencies` немає жодної сторонньої runtime-залежності (усі завдання розбору, валідації, регулярних виразів, роботи з датами та колекціями реалізовані засобами стандартної бібліотеки `dart:core`).

У секції `dev_dependencies` підключено 2 офіційні пакети розробки:

1. **`lints: ^6.0.0`**
   - **Призначення**: забезпечує офіційний рекомендований набір правил статичного аналізатора Dart (`package:lints/recommended.yaml`), підключений у `analysis_options.yaml` для перевірки відповідності стандартам Effective Dart.
   - **Розглянуті альтернативи**:
     - `very_good_analysis` — сторонній суворий набір лінтів від Very Good Ventures; не обраний, оскільки вимогою завдання є стандартний пакет `package:lints/recommended.yaml`.
     - `flutter_lints` — призначений для Flutter-проєктів із UI-залежностями, тому надлишковий для консольного Dart-пакета.

2. **`test: ^1.25.6`**
   - **Призначення**: стандартний фреймворк модульного тестування для перевірки коректності функцій розбору, валідації, конвеєрів та формування звіту командою `dart test`.
   - **Розглянуті альтернативи**:
     - Власні перевірки через `assert` у `main()` — не забезпечують ізольованого запуску тестів та інформативних звітів про помилки.
     - `checks` — експериментальна бібліотека тверджень, яка все одно потребує `package:test` як тестового раннера.
