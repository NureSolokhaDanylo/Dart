# Book Catalog (`book_catalog`)

Навчальний проєкт із розроблення програмного забезпечення мовою **Dart** (SDK `^3.13.2`).

---

## Лабораторна робота №1: Функції та колекції (`branch: lab1`)

Консольна програма для безпечного розбору, валідації, фільтрації, групування, сортування та агрегації записів предметної області **«Каталог книг бібліотеки»** без використання класів (`class`).

---

## Лабораторна робота №2: Об’єктно-орієнтована модель предметної області (`branch: lab2`)

Перенесення функціональної моделі Лабораторної роботи №1 на об’єктно-орієнтовану архітектуру (`Book`, `BookFormat`, `CatalogExportable`, `Repository<T extends Identifiable>`, `BookGenre`).

---

## Лабораторна робота №3: Асинхронна та паралельна обробка даних (`branch: lab3`)

Доповнення ООП-моделі асинхронним шаром доступу до даних (`AsyncRepository<T>`), потоковою обробкою подій (`Stream`, `async*`, `StreamController`) та паралельними обчисленнями в окремих ізолятах (`Isolate.run`), покритих модульними тестами `package:test`.

### 1. Обґрунтування вибору архітектури та типів даних

1. **Асинхронний шар доступу (`lib/async_repository.dart`)**:
   - Клас `AsyncRepository<T extends Identifiable>` інкапсулює асинхронні операції `load`, `loadOrThrow`, `save`, `delete`, `loadAll` (кожна повертає `Future`) та потоковий генератор `watchAll` (`Stream<T>` через `async*`).
   - Для порівняння обробки групових помилок використано як стандартний `Future.wait`, так і розширення `Iterable<Future<T>>.wait`, яке генерує `ParallelWaitError<List<Book?>, List<AsyncError?>>`, зберігаючи успішні результати паралельних запитів.

2. **Потокова модель подій (`lib/stream_processor.dart`)**:
   - Події предметної області змодельовано запечатаною ієрархією `sealed class CatalogEvent` (`BookAddedEvent`, `BookRatingUpdatedEvent`, `BookLoanStatusChangedEvent`).
   - Використано як одноразові (`StreamController<CatalogEvent>`), так і широкомовні (`StreamController<Book>.broadcast()`) контролери потоків. Кожна підписка через `.listen()` зберігає об’єкт `StreamSubscription` і явно скасовується викликом `await subscription.cancel()`.

3. **Паралельні обчислення в ізолятах (`lib/isolate_worker.dart`)**:
   - Ресурсоємний синхронний розрахунок поліноміальної сигнатури FNV-1a та перевірки простих дільників над великим синтетичним масивом видань винесено у фонові потоки виконання за допомогою `Isolate.run`.

---

### 2. Обґрунтування використання `!`, `late` та `dynamic`

У всій кодовій базі проєкту (`lib/`, `bin/`, `test/` для ЛР1–ЛР3):
- **Оператор `!` (null assertion operator)** — **не використовується (0 входжень)**.
- **Ключове слово `late`** — **не використовується (0 входжень)**. Навіть у модульних тестах із `setUp` змінні ініціалізуються безпечними початковими екземплярами без `late`.
- **Тип `dynamic`** — **не використовується (0 входжень)**. Усі асинхронні функції, потоки, ізоляти та помилки мають явні статичні типи.

---

### 3. Обґрунтування сторонніх залежностей із `pub.dev`

У секції `dependencies` сторонні пакети відсутні (використано стандартні бібліотеки `dart:core`, `dart:async`, `dart:isolate`).

У секції `dev_dependencies`:
1. **`lints: ^6.0.0`** — офіційний набір правил статичного аналізатора (`package:lints/recommended.yaml`) із додатково увімкненими правилами `unawaited_futures` та `discarded_futures` для суворого контролю очікування `Future`.
2. **`test: ^1.25.6`** — стандартний фреймворк модульного тестування Dart (`group`, `setUp`, `expectLater`, матчери `completion`, `throwsA`, `emitsInOrder`, `emitsDone`).
